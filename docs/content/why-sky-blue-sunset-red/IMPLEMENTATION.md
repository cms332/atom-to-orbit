# 하늘색 이야기 구현 기록

2026-10-28 (KST). 소유자가 제공한 `A2O_Sky_Colors_Codex_Pack.zip`의 원고·명세·참고 계산을 읽고 기사 추가와 공개 배포를 요청했다. 여섯 번째 과학 이야기로 `/articles/why-sky-blue-sunset-red/`에 연결한다. 발행일은 실제 작업일을 메타데이터에만 기록하며 작성일·읽기 시간은 본문 헤더에 표시하지 않는다.

## 편집과 출처

- 초등학생이 읽을 수 있는 네 절의 원고를 적용한다. 같은 햇빛, 파장, 분자와 산란, 낮은 태양에서 길어지는 경로 순서다. 파란 하늘의 산란광과 노을의 직접광·주변 산란을 구분하고 파란빛이 빨간빛으로 바뀐다고 설명하지 않는다.
- NASA Space Place, Met Office, NWS, NOAA JetStream, UCAR와 NASA 관찰 주의 자료를 확인했다. 정량 모형은 Feynman의 레이리 산란 설명과 pvlib 공식 문서·공개 구현을 대조한다. Kasten–Young 논문 DOI는 pvlib이 인용한 원 출처로 연결하며 전문 열람을 주장하지 않는다.
- 본문에는 작은 번호 링크, 하단에는 하나의 접힌 출처 목록을 둔다. 보라색 하늘 설명과 계산 방법도 기본으로 접는다. 기존 별빛 이야기로 이어지는 링크, 실제 목록·홈·사이트맵·canonical·OG·Article 메타데이터를 재사용한다.
- 일러스트와 썸네일은 직접 제작한 SVG다. 외부 사진·삽화·로고를 복제하지 않는다. 새 의존성·추적 이벤트·API·날씨 서비스는 추가하지 않는다.

## 모형의 경계

- `src/lib/data/sky-colors.ts`에 450/550/650nm를 SI 미터로 저장한다. 상대 산란 계수는 `(550nm/λ)^4`, 상대 공기량은 Kasten–Young 1989, 각 파장 자체의 입력을 1로 놓은 직접 통과 비율은 `exp(-0.1 × 계수 × 공기량)`이다.
- 광학 깊이 0.1은 설명용 설정이다. 입력 태양 스펙트럼·복수 산란·먼지·구름·색 감각을 계산하지 않는다. 세 비율을 RGB 색이나 합계 100%의 구성비로 바꾸지 않으며 `1−T`를 관찰자의 하늘 밝기로 간주하지 않는다.
- 태양 높이 조작 범위 5°–80°, 높은 프리셋 70°, 낮은 프리셋 5°다. 정오·일몰·특정 장소의 실제 태양 위치에 대응시킨 값이 아니다. 상태 문구의 경계 15°/50°도 교육적 편집값이다.
- 풍경의 색은 계산과 독립적인 정성적 연출이다. 같은 육지 풍경을 유지하고 지평선만 따뜻해지며 위쪽에는 푸른빛이 남는다.
- 빛 도식의 고정된 곡면 공기층은 알아보기 위한 과장이다. 그림의 픽셀 길이를 물리 거리나 Kasten–Young 상대 공기량으로 환산하지 않는다. 공기 중 경계 교차점과 산란 지점을 계산하며 태양이 낮을수록 경로가 길어진다. 태양→공기→눈과 태양→흰 면을 나누고, 각 파장의 선 색은 유지한다. 빨간빛의 산란과 파란빛의 직접 통과도 남긴다.

## 접근성·검증

- 네이티브 버튼·range, 선택 상태, DOM 설명, 서로 다른 선 패턴을 제공한다. 프리셋·슬라이더 조작 완료 때 상태를 알리며 프레임마다 낭독하지 않는다.
- 강조는 요청할 때만 2초간 한 번 진행한다. 실제 광속 재현이 아니다. 높이 변경·초기화·화면 밖·탭 숨김·컴포넌트 해제 때 타이머를 정리한다. 움직임 줄이기에서는 정적으로 두 경로를 강조한다.
- JS 없이도 높은/낮은 태양의 두 정적 그림, 본문, 비교표, 계산과 출처, 퀴즈 정답이 읽힌다. 작동하지 않는 버튼은 표시하지 않는다.
- 단위 검사: 공식 기준값, 파장 의존성, 세 통과값, 전 범위 단조성, 입력 검증, 고정 공기층 안의 산란·입사 각도. 브라우저 검사: 320/390/768/1440px, 200% 글자, 키보드·강조 수명·reduced-motion·JS 없음·퀴즈·출처·메타데이터와 기존 기사 회귀.
- 패키지 참고 함수의 Node 테스트 14개를 실행해 통과했다. 저장소의 실제 코드·UI 검사 결과는 진행 기록에 별도로 기록한다. 캡처와 검사 원본은 `artifacts/sky-colors/`에 둔다.

## 배포

소유자가 이번 기사 배포까지 명시적으로 요청했다. 로컬 검사 후 보호된 main의 PR·정확한 병합 커밋 CI 통과를 거쳐 기존 배포 스크립트를 사용한다. 실제 배포 소스·패키지 해시·검증 결과는 실행 후 GitHub production Deployment와 배포 태그에 기록한다. 소스 커밋 작성 시점의 계획을 배포 완료 기록으로 취급하지 않는다. 증거 파일은 `artifacts/sky-colors-deployment/`에 저장한다. A2O는 최신 정상 컨테이너 하나만 유지하며 HGI·공용 분석 DB·DNS는 변경하지 않는다.
